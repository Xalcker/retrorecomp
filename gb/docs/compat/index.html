Cómo se probó

Etapa 1, todas las ROMs: cada ROM corre en el intérprete (gbtest) con la consola que elige el runtime en automático (Game Boy Color si el cartucho lo admite, si no Super Game Boy si lo admite, si no Game Boy) y entradas guionadas (Start, A, B, flechas), y se toman capturas en los cuadros 450, 900 y 1500. «Corre» significa que cargó, no ejecutó un opcode ilegal y la captura más colorida no es de un solo color; no garantiza que el juego se vea bien: las capturas de la tabla hay que revisarlas a ojo.

Etapa 2, una selección por MBC y consola: gbrecomp (solo análisis estático), compilar el proyecto generado y correr difftest con las semillas 1 y 2 (3600 cuadros cada una, un minuto de juego con el mando al azar), que compara el estado completo (CPU, ciclos, RAM, VRAM, OAM, registros, timer, PPU, RAM del cartucho) contra el intérprete al final de cada cuadro. Si algo cayó al intérprete en ROM, se recompila con esas direcciones (--uncovered → --trace) y se repite. «Recompilado» = sin diferencias en todas las rondas. «Recompilado %» es la fracción de instrucciones ejecutadas por código recompilado en el peor caso de la última ronda (lo que falta suele ser código en RAM). La velocidad es la de difftest --bench (recompilado / intérprete, sin ventana ni límite de cuadros).

Para repetirlo: uv run tools/compat/scan.py DIR_GB DIR_GBC, uv run tools/compat/run.py y uv run tools/compat/report.py (ver el README).
